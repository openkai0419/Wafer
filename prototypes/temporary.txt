# prototypes ディレクトリ概要メモ (設計思想 / 責務整理)

## 全体目的
画像ビューア本体への導入前段階として、コマンド体系・メニュー構築・入力デバイス(マウス/ショートカット)バインディングの拡張フレームワークを試作。単一責務・疎結合・再利用性・階層的IDによる柔軟な拡張を検証。

## コア概念
- CommandMeta / CommandParam: コマンドの静的メタ情報(表示名・引数・ホットキー・アイコン・オプション有無・チェック可能性)。
- CommandBase / create_command_from_meta: メタ情報から即席クラス生成。ロジックは meta.func を包む最小構造。Undo など拡張を将来可能にする余地。
- CommandRegistry: シングルトン。ID(=パス終端)でコマンドクラスを動的呼び出し。Payload(引数セット)も処理。重複ID防止と最低限の存在検証のみで軽量。
- CommandPayload: 実行要求のシリアライズ可能オブジェクト。イベント経由/永続化/エディタ間受け渡しを簡易化。

## メニュー体系
- RegistryBackedMenu: create_definitions() が 文字列トークン + 定義(dict) を返し、正規化→レジストリ登録→MenuHub 集約。
  - トークン種別: セクション(":Label"), セパレータ("-")。階層は path 文字列 "a/b/c"。
  - path の最終要素が command id となる。重複チェックあり。
- MenuHub: 全 menu クラスからパス/表示構造を集約。フォルダ(途中階層)単位の検索・再ベース化・再構築を支援し、UI側が柔軟に再編成可能。
- MenuBuilder / CommandMenuBuilder: MenuHub 情報 + CommandRegistry を利用し Qt メニューへ動的具現化。フォルダセグメント/セクション/コマンド表示は t.tr() により実行時に翻訳。ID/パスは英語のまま固定。
  - 動的オプションダイアログ表示 (CommandOptionsDialog)。
  - チェック可能コマンドは内部状態 _check_states でメニュー再構築不要の軽量反映。
  - selection_callback により "選択" と "実行" モードを分離、オプション付き選択も許可。
  - context_provider をチェーン合成可能 (chain_providers)。Widget 毎の文脈差分統合。

## オプション永続化
- CommandOptionStore: .command_options.json にコマンド毎の引数デフォルトを保存。初回アクセス時遅延ロード。set/get/clear のみの最小 API。
- 起動後の再編集→保存→次回実行時に補完 (チェック状態は別途メニュー側保持)。

## 入力バインディング体系
- BindingManager: mouse_bindings.json をロード or デフォルトシード。登録 Widget 群へ一括適用。スコープ(Widget 名)別にマッピング。
- CommandBindingMixin: Widget に組み込み、MouseEventManager / ShortcutManager を初期化。CommandPayload 単位で統一処理。provider() で追加コンテキスト挿入。
  - 直接バインド + ストア解決フォールバックの二層。イベント未割当時はストア検索で柔軟さ確保。
  - バインディング時のオプションダイアログでキャンセルした場合は登録を中止し、既存設定を変更しない。
- 編集 UI: MouseBindingEditor と新規 KeyBindingEditor。
  - KeyBindingEditor: 旧 ShortcutBindingEditor を置換。マウス編集 UI パターンを転用し、ショートカット列挙 + 1 つ選択→グローバル("*")とウィジェット別オーバーライドを編集。追加/削除/リセット機能。
  - KeyBindingEditor: 旧 ShortcutBindingEditor を置換。マウス編集 UI パターンを転用し、ショートカット列挙 + 1 つ選択→グローバル("*")とウィジェット別オーバーライドを編集。追加/削除/リセット機能。互換性: 旧呼び出し `ShortcutBindingEditor(ws, cmds)` を維持するため __init__ に commands 引数をオプション追加し無視可能 + `ShortcutBindingEditor = KeyBindingEditor` エイリアス。
  - 内部ストア KeyBindingStore: key_bindings.json 永続化。形式 {"Ctrl+S": {"*": {id,args}, "paneA": {...}}}。CommandPayload をシリアライズし再構築。
  - 適用時: 各 Widget の set_shortcut_bindings に対しスコープ優先 (widget 名 > "*") で束ねて渡す。
  - UI 遷移: 左ペイン QListWidget + QKeySequenceEdit 追加行、右ペインで選択中シーケンスの編集セクション (グローバル + オーバーライド群)。

## デモ構造
- menu_demo.py: 複数の RegistryBackedMenu 実装 (FileMenu / PathMenu / CmdMenu / ContextMenu / MenuMenu) で多階層・オプション・チェック・動的構築パターンを提示。
- demo_app.py: MainWindow 内に複数 DemoPane を配置し scope 別バインディング挙動を確認。MenuBuilder.use("binding") により特定フォルダ絞り込みメニュー。
- CmdMenu に choices を用いたサンプル `Options/mode` を追加し、選択式引数の UI/実行フローを検証可能。

## 設計上の狙い
1. パスベース ID により: 階層再編/部分的リベース/フォルダ単位抽出を容易化。
2. Meta <-> 実行ロジック分離: 将来 undo/redo, async, 権限検査挿入が可能。
3. シリアライズ容易性: Payload / オプションストア / バインディングストアが全て JSON 互換。
4. UI 動的生成: パラメータ型に応じた簡易ウィジェット工場 (bool/int/float/str/choices)。追加型は widget_type 拡張で差し替え予定。
5. Scope ベースバインディング: 同一コマンドをコンテキスト差分で再利用 (ex. pane 毎に引数変更)。トグル系コマンドは永続ストアで状態を保持し、メニュー/バインディング双方で正しく反転・復元。

## 現状の制限 / 課題
- 例外時多くが silent pass。ユーザー通知/ログ集約層が未整備。
- CommandOptionsDialog で型変換失敗時のフィードバック欠如。
- チェック状態永続化なし (アプリ再起動で失われる)。必要なら OptionStore 拡張。
- MenuHub.collect_items_by_folder の構築アルゴリズムが複雑かつ O(N*M)。キャッシュ導入余地。
- BindingManager と OptionStore がファイル IO を直接行うため並列アクセス/競合未考慮。
- undo/redo インターフェイスはスタブ (CommandBase.undo)。履歴管理未実装。
- パラメータ validation (min/max) は UI セット段階のみ、直接呼び出し時は非検証。

## 2025-11-15 入力解決の微修正
- 右ボタン押下中にカーソル移動して左クリックした場合でも、左クリック時点のカーソル直下にあるバインディング対象ウィジェットへイベントを転送するように変更。
- 実装要点: MouseEventDispatcher が MouseButtonRelease 処理時に `QApplication.widgetAt(global_pos)` で再ヒットテストし、登録済みウィジェットへ座標変換した QMouseEvent を生成してディスパッチ。適切な対象が見つからない場合は従来通り自己ウィジェットで処理。
- ダブルクリック判定・ドラッグ開始閾値の挙動は従来通り維持。
 - ダブルクリックにバインドが存在しない場合、2 回目のクリックはシングルクリックとして解決し実行するように変更。実装上は fallback 解決で DOUBLE 未割当時に同一ボタン/同一修飾の SINGLE を再解決して実行。
 - ボタン同時押し(held あり)のアクションが実行されたシーケンスでは、参加ボタンのその後の単独リリース時(SINGLE)は抑制し、重複実行を防止。
 - バインドエディタで「なし(解除)」選択しても解除されない不具合を修正。グローバルスコープ("*")の一時ペイロードを確実に破棄し、適用時に再登録されないようにした。

## 2025-11-15 キー入力の安定化
- アプリ/ウィンドウの非アクティブ化時に押下状態を全クリア。`ShortcutManager` が `ApplicationDeactivate`/`WindowDeactivate` を受信すると、全ウィジェットの `_pressed/_pressed_sc/_fired/_consumed` をリセットする。
- `eventFilter` がアプリケーション対象イベントでも動作するように先頭で種別判定を追加。従来のウィジェット限定ハンドリングに加えてグローバルな状態遷移を確実に捕捉。
- ウィジェット単位でも `FocusOut/Hide/WindowDeactivate` で同様にクリアする共通処理を導入し、Alt+Tab や別ウィンドウへのフォーカス移動時に押下ゴーストが残らないようにした。
- 既存の論理キー/物理スキャンコードの二系統判定は維持。2 キー同時の発火は押下時、単独は未消費のリリース時に解決。

エディタのデバッグ表示に関する補足:
- KeyBindingEditor のデバッグ欄は内部で独自に押下集合を保持していたため、非アクティブ化時に Release が届かないと表示が残留した。Editor 自身がアプリ/ウィンドウの非アクティブ化および FocusOut/Hide をフックして集合と表示を即時クリアするように変更し、見た目の不整合を排除した。

限界/今後の検討:
- Qt 標準 API では非修飾キーの現在状態を外部から問い合わせる手段が限られるため、OS レベルのキー状態と完全同期は保証できない。Windows 専用で `GetAsyncKeyState` を用いるポーリング補助は可能だがクロスプラットフォーム性を損なうため現状は採用しない。
- IME 合成中のキーイベントやレイアウト切替直後の一部キーは通知順序が前後する場合がある。今回の非アクティブ時リセットで大半の実害は回避可能。

## 2025-11-16 KeySequence クラスの導入とキー管理の統一（最終版）
- 文字列の "+" 結合によるキー管理を完全排除し、専用の `KeySequence` クラスとJSON構造化形式で統一管理:
  - `KeySequence`: 最大2つのキーをタプルで管理する専用クラス。内部的に tuple で保持。
  - `from_dict(data)`: {"modifier": "Shift", "key": "F10"} 形式の辞書から生成。modifier省略時は単一キー。
  - `to_dict()`: {"modifier": "Shift", "key": "F10"} または {"key": "H"} 形式の辞書に変換（JSON保存用）。
  - `to_tuple()`: 内部タプルを取得。
  - `modifier` / `key` プロパティ: 装飾キーと主キーに個別アクセス。
  - `__eq__`, `__hash__`: 辞書キーとして使用可能。
  - `__lt__`: ソート用の比較演算子を実装し、`str()` なしで直接ソート可能。
  - `__str__()`: "Shift+F10" 形式の文字列表現（表示用のみ）。
- JSON保存形式の変更:
  - 旧: `{"Ctrl+S": {"*": {id, args}, "scope": {...}}}`（互換性完全排除）
  - 新: `[{"modifier": "Ctrl", "key": "S", "scopes": {"*": {id, args}, "scope": {...}}}, ...]`
  - mouse_bindings.json と同様の構造化配列形式に統一。
- 変更箇所:
  - `KeySequence`: `to_display/from_display` を完全削除。表示は `__str__()` のみ。文字列変換メソッドを一切提供せず。
  - `KeyBindingStore`: 保存・読込ともに配列形式のみ対応。旧辞書形式の互換性コードを完全削除。内部データは `Dict[KeySequence, Dict[str, CommandPayload]]` で管理。
  - `KeyBindingEditor`: 全体的に KeySequence ベースに書き換え。`_draft` も `Dict[KeySequence, ...]` に変更。バインディング辞書は KeySequence オブジェクトをキーとして使用（文字列化なし）。表示時は `str(seq)` を使用。ソートは `__lt__` を利用した `sorted(seqs)` で直接実行。
  - `ShortcutManager`: `set_bindings()` の引数を `Dict[str, Any]` から `Dict[KeySequence, Any]` に変更。`_parse_key_sequence(seq: KeySequence)` メソッドを追加し、KeySequence から FrozenSet[int] への変換を実装。旧 `_parse_string_combo()` は互換性のため保持。
  - `BindingManager`: `_is_sc_combo` を `_is_physical_seq` に変更し KeySequence を直接受け取る。`store_logical` と `store_physical` は KeySequence オブジェクトをキーとして直接使用（文字列化なし）。
  - `_SingleKeyCaptureDialog`: 1つのキーのみ入力可能に変更。既にキーが入力されている場合は追加入力を無視。
  - `_TwoKeyCaptureDialog`: 最大2キーまでに制限。3個目以降のキーは無視。各LineEditに1キーずつ表示。`_current_combos` を `_final_keys` に単純化。
- 互換性: 旧形式との互換性を完全排除。新規インストールまたは手動での再設定が必要。
- str(KeySequence) 使用箇所の完全排除: 表示用の `__str__()` 以外は KeySequence オブジェクトを直接使用。ソート、辞書キー、引数渡しはすべて KeySequence オブジェクトのまま処理。

## 2025-11-16 ShortcutManager の責務分離とクラス化 → ファイル統合完了
- キー押下状態管理とキー名解決ロジックを専用クラスに分離し、ShortcutManager の肥大化を解消:
