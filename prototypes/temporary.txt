# prototypes ディレクトリ概要メモ (設計思想 / 責務整理)

## 全体目的
画像ビューア本体への導入前段階として、コマンド体系・メニュー構築・入力デバイス(マウス/ショートカット)バインディングの拡張フレームワークを試作。単一責務・疎結合・再利用性・階層的IDによる柔軟な拡張を検証。

## コア概念
- CommandMeta / CommandParam: コマンドの静的メタ情報(表示名・引数・ホットキー・アイコン・オプション有無・チェック可能性)。
- CommandBase / create_command_from_meta: メタ情報から即席クラス生成。ロジックは meta.func を包む最小構造。Undo など拡張を将来可能にする余地。
- CommandRegistry: シングルトン。ID(=パス終端)でコマンドクラスを動的呼び出し。Payload(引数セット)も処理。重複ID防止と最低限の存在検証のみで軽量。
- CommandPayload: 実行要求のシリアライズ可能オブジェクト。イベント経由/永続化/エディタ間受け渡しを簡易化。

## メニュー体系
- RegistryBackedMenu: create_definitions() が 文字列トークン + 定義(dict) を返し、正規化→レジストリ登録→MenuHub 集約。
  - トークン種別: セクション(":Label"), セパレータ("-")。階層は path 文字列 "a/b/c"。
  - path の最終要素が command id となる。重複チェックあり。
- MenuHub: 全 menu クラスからパス/表示構造を集約。フォルダ(途中階層)単位の検索・再ベース化・再構築を支援し、UI側が柔軟に再編成可能。
- MenuBuilder / CommandMenuBuilder: MenuHub 情報 + CommandRegistry を利用し Qt メニューへ動的具現化。フォルダセグメント/セクション/コマンド表示は t.tr() により実行時に翻訳。ID/パスは英語のまま固定。
  - 動的オプションダイアログ表示 (CommandOptionsDialog)。
  - チェック可能コマンドは内部状態 _check_states でメニュー再構築不要の軽量反映。
  - selection_callback により "選択" と "実行" モードを分離、オプション付き選択も許可。
  - context_provider をチェーン合成可能 (chain_providers)。Widget 毎の文脈差分統合。

## オプション永続化
- CommandOptionStore: .command_options.json にコマンド毎の引数デフォルトを保存。初回アクセス時遅延ロード。set/get/clear のみの最小 API。
- 起動後の再編集→保存→次回実行時に補完 (チェック状態は別途メニュー側保持)。

## 入力バインディング体系
- BindingManager: mouse_bindings.json をロード or デフォルトシード。登録 Widget 群へ一括適用。スコープ(Widget 名)別にマッピング。
- CommandBindingMixin: Widget に組み込み、MouseEventManager / ShortcutManager を初期化。CommandPayload 単位で統一処理。provider() で追加コンテキスト挿入。
  - 直接バインド + ストア解決フォールバックの二層。イベント未割当時はストア検索で柔軟さ確保。
  - バインディング時のオプションダイアログでキャンセルした場合は登録を中止し、既存設定を変更しない。
- 編集 UI: MouseBindingEditor と新規 KeyBindingEditor。
  - KeyBindingEditor: 旧 ShortcutBindingEditor を置換。マウス編集 UI パターンを転用し、ショートカット列挙 + 1 つ選択→グローバル("*")とウィジェット別オーバーライドを編集。追加/削除/リセット機能。
  - KeyBindingEditor: 旧 ShortcutBindingEditor を置換。マウス編集 UI パターンを転用し、ショートカット列挙 + 1 つ選択→グローバル("*")とウィジェット別オーバーライドを編集。追加/削除/リセット機能。互換性: 旧呼び出し `ShortcutBindingEditor(ws, cmds)` を維持するため __init__ に commands 引数をオプション追加し無視可能 + `ShortcutBindingEditor = KeyBindingEditor` エイリアス。
  - KeySequenceSection に「割当」ボタンを追加し、_TwoKeyCaptureDialog による新しいキーシーケンスの取得と、既存割当の置き換えを即時反映可能にした。
  - 左ペインのリストは (すべて) を先頭、(なし) を次に固定し、それ以外はカスタム順で整列。順序は 装飾 → 特殊 → その他 → ナビ → 数字 → アルファベット。
  - 右ペインのセクションは主キー優先で並び替え（装飾 → 特殊 → その他 → ナビ → 数字 → アルファベットの順、その中で修飾キー優先度順）。
  - KeySpecCatalog を追加し、バインド可能キーの分類と表示順を一元管理。UI は KeySpecCatalog の API に依存し、ハードコードを回避。
  - 内部ストア KeyBindingStore: key_bindings.json 永続化。形式 {"Ctrl+S": {"*": {id,args}, "paneA": {...}}}。CommandPayload をシリアライズし再構築。
  - 適用時: 各 Widget の set_shortcut_bindings に対しスコープ優先 (widget 名 > "*") で束ねて渡す。
  - UI 遷移: 左ペイン QListWidget + QKeySequenceEdit 追加行、右ペインで選択中シーケンスの編集セクション (グローバル + オーバーライド群)。
  - 補助操作: 先頭に "*" を表示し、空白クリック時は current を "*" に戻す。選択解除は行わない。

## デモ構造
- menu_demo.py: 複数の RegistryBackedMenu 実装 (FileMenu / PathMenu / CmdMenu / ContextMenu / MenuMenu) で多階層・オプション・チェック・動的構築パターンを提示。
- demo_app.py: MainWindow 内に複数 DemoPane を配置し scope 別バインディング挙動を確認。MenuBuilder.use("binding") により特定フォルダ絞り込みメニュー。
- CmdMenu に choices を用いたサンプル `Options/mode` を追加し、選択式引数の UI/実行フローを検証可能。

## 設計上の狙い
1. パスベース ID により: 階層再編/部分的リベース/フォルダ単位抽出を容易化。
2. Meta <-> 実行ロジック分離: 将来 undo/redo, async, 権限検査挿入が可能。
3. シリアライズ容易性: Payload / オプションストア / バインディングストアが全て JSON 互換。
4. UI 動的生成: パラメータ型に応じた簡易ウィジェット工場 (bool/int/float/str/choices)。追加型は widget_type 拡張で差し替え予定。
5. Scope ベースバインディング: 同一コマンドをコンテキスト差分で再利用 (ex. pane 毎に引数変更)。トグル系コマンドは永続ストアで状態を保持し、メニュー/バインディング双方で正しく反転・復元。

## 現状の制限 / 課題
- 例外時多くが silent pass。ユーザー通知/ログ集約層が未整備。
- CommandOptionsDialog で型変換失敗時のフィードバック欠如。
- チェック状態永続化なし (アプリ再起動で失われる)。必要なら OptionStore 拡張。
- MenuHub.collect_items_by_folder の構築アルゴリズムが複雑かつ O(N*M)。キャッシュ導入余地。
- BindingManager と OptionStore がファイル IO を直接行うため並列アクセス/競合未考慮。
- undo/redo インターフェイスはスタブ (CommandBase.undo)。履歴管理未実装。
- パラメータ validation (min/max) は UI セット段階のみ、直接呼び出し時は非検証。
 - KeyBindingEditor のキーキャプチャダイアログ(_TwoKeyCaptureDialog)の確定基準を「最後に押された時点のキー状態」に変更。解放直前ではなく、押下時スナップショットを用いて同時押しが単一化されないように修正。OK押下時も未確定ならこのスナップショットで確定。

## 改善提案 (短期)
- 例外処理方針更新: show_error は GUI ダイアログ廃止し stderr 出力 + RuntimeError 送出へ変更。silent pass を削減し例外は端末へ直接表示。
- CommandParam: Generic[T] 化し型安全性向上。choices と type 整合検査。
- オプションダイアログ: widget_type 明示でカスタムファクトリ登録。FactoryRegistry 導入。
- 多言語化: display / description を翻訳キー化。TranslatorMixin を prototypes にも適用。
 - UI 統一: MouseBindingEditor 右ペインを QScrollArea の NoFrame + 透過背景に変更し、KeyBindingEditor と同一の黒背景表示に統一。

## 改善提案 (中期)
- undo/redo 層: CommandBase に result / inverse_args 帯域。CommandRegistry へ stack 実装。
- 非同期実行: meta に async フラグ、UI から await 実行 + 進捗通知。
- プラグインロード: menu 定義モジュールを plugins/ 以下から動的 import。署名/バージョン管理予定。
- コンテキスト権限: provider() 返却値に permission を含め CommandRegistry 実行前検証。

## 拡張ポイント
- 新規コマンド: RegistryBackedMenu.create_definitions() に dict 追加。path 最後が id。
  多言語対応: path の各セグメント文字列（例: "Options", "Toggle"）とセクションラベル（":File" 等）、CommandMeta.display に対応する英語キーを translations.json に用意。内部検索・バインディングは id/path を使用し、表示のみ翻訳。
  top-level フォルダメニュータイトルも MenuBuilder.use() で t.tr() を適用済み。
- 新規メニュー: path_prefix と定義リストを持つクラス作成するだけで自動登録。
- 新規入力デバイス: BindingManager 相当の抽象層 + Mixin を追加し既存パターン踏襲。
- 新規パラメータ型: CommandOptionsDialog._create_widget にファクトリ差し込み。
